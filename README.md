# Replication artifact (anonymized snapshot)

Companion to the submission *Evidence-Grounded Architecture Recovery and Governance for C/C++
and C# Systems*. The tool is called `Anon` here (name scrubbed, see `ANONYMIZATION.md`); its own
README is `README-tool.md`. Everything a reviewer needs to (1) regenerate every table and
in-prose number of the paper from the raw run artifacts, (2) run the pipeline end-to-end on a
bundled toy fixture, (3) run the test suite, and (4) inspect the protocol history
(`PROTOCOL-HISTORY.md`). Snapshot, not a git history.

## Layout

|---|---|

| `baselines/`, `mutate/` | the experiment harness: ARCADE runner + ARC/WCA/LIMBO Java drivers, LLM-recovery baseline (`baselines/llm_recovery.py` holds the prompt), ablations, perf, RQ9 (`baselines/rq9_blind_curation.py`), the mutation operators |

| `protocol/`, `PROTOCOL-HISTORY.md` | the evaluation plan's protocol sections (verbatim extract) and the dated commit history of every protocol document; the runbooks themselves live in `docs/` |
| `ARTIFACT-MANIFEST.json` | per-file SHA-256 of this snapshot |
| `README-tool.md` | the tool's own README, written for this snapshot: what the pipeline does, how to install and run it, the CLI, the fact model, the file lifecycle, the test gates, the LLM rules — self-contained, no links outside the package |
| `CONTRIBUTING.md` | the contributor contract a repository adopts with the tool (regenerate, never hand-edit, attach the drift report); its "plan §" citations point at the design plan, which is not in this snapshot (§5) |

Systems with raw artifacts here: abseil, bash, eshop, eshop-role, eshop-rq9, eshop-rq9-R-B, fmt, itk, libxml2, nopcommerce, nopcommerce-name, opencv, opencv-mod, orchardcore, orchardcore-cat, orleans, serilog, squidex, squidex-rq9, terminal, toy.

## RQ numbering: plan ids vs paper numbers

The paper numbers its research questions consecutively (RQ1–RQ7). Everything in this
package keeps the **evaluation plan's** ids instead (the internal documents call them the
"pre-registered" ids): the `axis` column of `analysis/results.csv` (`RQ6-hist`, `RQ9`, …), the
table file names (`latex/tables/rq6_*.tex`, `rq9_*.tex`), the macro prefixes
(`\rqSix…`, `\rqNine…`), the harness names (`mutate/run_rq6.py`, `baselines/rq9_blind_curation.py`)
and the runbooks. Only the rendered captions and the prose carry the paper number, via
`PAPER_RQ` in `analysis/make_tables.py`, which is also the source of this table:

| plan id (used in this package) | paper number |
|---|---|
| RQ1 | RQ1 |
| RQ2 | RQ2 |
| RQ3 | RQ3 |
| RQ4 | — (deferred companion study, not in the paper) |
| RQ5 | RQ4 |
| RQ6 | RQ5 |
| RQ7 | RQ6 |
| RQ8 | — (deferred companion study, not in the paper) |
| RQ9 | RQ7 |

**Plan citations.** Several shipped documents (`CONTRIBUTING.md`, `analysis/README.md`,
`mutate/README.md`, `schema/CHANGELOG.md`, `references/README.md`, the runbooks in `docs/`) cite
sections of the authors' internal design and evaluation plans as "plan §N" or "eval §N". Those
plans are not in this snapshot (they name people and the organisation throughout, §5); the
sections that define the study protocol — fairness controls, drift stopping rules, the
blind-curation design, the statistical analysis plan, threats — are extracted verbatim in
`protocol/eval-plan-extract.md` with their original numbering, so an "eval §12" citation
resolves there. Any other "§N" is background rationale, not something a replication depends on.

## 0. What reproduces from what

Every result row falls into one of four reproducibility classes (the paper's Data Availability
statement gives only this package's URL; the classes are documented here). Where each class lives:

| class | rows | how |
|---|---|---|
| fully reproducible from this package | every open-source system except nopCommerce and libxml2 (their `-role` / `-cat` / `-name` / `-mod` / `-rq9` curation variants included) | §1 regenerates the tables from the shipped raw runs; §4 re-runs the pipeline and the SAR baselines from the pinned commits and the shipped `references/<sys>/reference.rsf` |
| reproducible only after separately obtaining licensed or third-party inputs; raw outputs ship | nopCommerce (source under the nopCommerce Public License; reference transcribed from its documentation, withheld), libxml2 (reference converted from an unlicensed third-party package, withheld) | the scored outputs under `out/{nopcommerce,libxml2}/baseline/` regenerate the rows (§1); re-scoring needs the reference rebuilt as `references/<sys>/README.md` describes |
| verifiable from the shipped raw outputs, not rerunnable | the LLM-recovery baseline (`llm` rows; a hosted model); the human-produced RQ9 records and RQ6 real-history labels | replies and per-rerun clusters under `out/<sys>/baseline/llm-*/`, scored by the shipped scorer (a rerun needs an endpoint and will not reproduce the replies); the human records under `references/<sys>/{blind-curation,history}/` with their protocols in `docs/` |
| corroborating only | the industrial system `P-1` (`tier=P` rows) | `export-anon/` carries metrics only, no inputs; excluded from every inferential statistic |

## 1. Regenerate the tables and macros

Python ≥ 3.10. The analysis stages are stdlib-only except the planned inferential tests
(`stats.py`: Friedman/Nemenyi, Wilcoxon-Holm with matched-pairs rank-biserial r / Cliff's δ,
Wilson intervals, exact McNemar) which need the `[stats]` extra — without it
`stats.py` refuses to overwrite `stats.json` (pass `--allow-missing-scipy` to accept `TBD`
p-values).

```
python -m venv .venv && .venv/Scripts/activate     # or: source .venv/bin/activate
pip install -e ".[dev,stats]"
cd analysis
python aggregate_results.py --anon ../export-anon/results-anon.csv
python stats.py
python make_tables.py
python make_macros.py
```

This rewrites `analysis/results.csv`, `analysis/stats.json`, `latex/tables/*.tex` and
`latex/generated/macros.tex`; byte-identical to the shipped ones when run over this tree
(the build-time verification record is `ARTIFACT-MANIFEST.json` → `build_report.verification`:
fresh venv, `pytest`, this regeneration diffed against the shipped files, two toy runs).
`--anon` merges the Tier-P rows (`tier=P`, rendered after the OSS corpus and marked ‡; they are
excluded from every planned statistic by `stats.py`). Without `--anon` the tables lack
the `P-1` rows and are otherwise identical. `make all` in `analysis/` does the same (needs
`make`; the wildcard picks up `export-anon/` automatically).

**Metrics and views.** Every technique × system fidelity row carries MoJoFM and a2a (plus the
rerun standard deviations for the LLM baseline and the cluster counts) in `analysis/results.csv`
(axis `fidelity`; one all-common entity projection for every technique, `projection` column),
and — post hoc, added at a reviewer's request (eval plan §12 (m)) — the adjusted Rand index
(`ari`, ×100, chance-corrected) and the `nested` share (percentage of a partition's clusters that
lie inside one reference cluster: over-splitting vs misgrouping). MoJoFM and a2a remain the
plan's metrics and the only ones under inferential tests; `ari`/`nested` are descriptive.
**c2c was not scored**: ARCADE's c2c metric ships in the pinned jar but was never run in this
study, so no c2c number exists here or in the paper. A per-system × technique pivot of the
fidelity rows (`analysis/fidelity-by-system.csv`, written by `make_tables.py`) ships when
present as a reading aid; `results.csv` remains the tidy source of record.

## 2. Run the pipeline on the toy fixture

```
pip install -e ".[dev]"
arch run --repo tests/fixtures/toy-repo --arch-dir out/toy-run/architecture \
         --rules-dir tests/fixtures/toy-repo/architecture/rules --no-llm
```

(`out/toy/` holds the toy artifacts as shipped; writing the run to `out/toy-run/` keeps them
pristine for a diff.) No SDK, compiler or LLM is needed for the toy fixture (C# build graph is a pure parse; the
Roslyn L2 helper and C++ toolchains degrade gracefully to L0 when absent). Outputs land in
`out/toy-run/architecture/generated/` (`extracted-facts.json`, `curated-facts.json`,
`generated-*.dsl`, `run-report.json`, `architecture-drift.md`). Run it twice into two
directories: the `generated-*.dsl` fragments are byte-identical and the fact models differ only
in the volatile `generated_at` stamp (the determinism gate; `arch diff` compares two runs).

**The Roslyn L2 helper (`csharp-helper/`) is not in this snapshot.** C# extraction therefore
runs at L0 (the `.sln`/`.csproj` build graph, a pure parse): the toy's `generated-components.dsl`
carries its containers and container edges but no `component` elements, and
`extracted-facts.json` records the helper as an unavailable extractor (coverage warning, not an
error). The evaluated C# systems' shipped `out/<sys>/architecture/generated/` artifacts were
produced WITH the helper; the RQ1/RQ2 scoring itself is at build-target granularity and does
not depend on L2. `tests/test_generate.py::test_toy_generate_byte_identical` checks the
component tier only when the helper is present, so the suite passes either way.

## 3. Run the tests

```
python -m pytest -q          # default: parallel, real-toolchain 'integration' tier deselected
python -m pytest -q -m ""    # everything (needs cmake/ninja/doxygen/dotnet on PATH)
```

`tests/test_golden.py` is the byte-identity gate over the toy fixture; `test_tier_p_kit.py`,
`test_llm_recovery.py`, `test_rq6_*.py`, `test_harness.py` cover the evaluation harness. The
whole default tier passes without the .NET SDK or the Roslyn helper (see §2).

## 4. Re-running the experiments (optional)

* SAR baselines (`baselines/run_arcade.py <sys>`): needs the pinned `ARCADE_Core.jar v1.2.0`
  under `tools/arcade/` (`python baselines/make_bundle.py --fetch` downloads it; URL in the
  script) and Java 17; `arc/wca/limbo` additionally the source clone and a JDK for the drivers.
* Pipeline runs on the real systems: re-clone the pinned fixtures (below) into `fixtures/<sys>`
  (`arch fetch`), then `arch run --repo fixtures/<sys> --arch-dir out/<sys>/architecture
  --rules-dir overlays/<sys>/architecture/rules --no-llm`; C# needs the .NET SDK, C++ cmake +
  Doxygen (`arch doctor` lists what is missing).
* LLM-recovery baseline (`baselines/llm_recovery.py`): the prompt is in the script; the replies
  actually used (5 reruns per system, `gpt-5.6-sol` on Azure AI Foundry) are shipped under
  `out/<sys>/baseline/llm-*/` and `llm-recovery-<gran>.json`, so nothing here needs an LLM
  endpoint.
* Seeded drift (`python -m mutate.run_rq6`), perf (`baselines/rq7_perf.py`), RQ9 scoring
  (`baselines/rq9_blind_curation.py`, protocol in `docs/rq9-blind-curation-runbook.md`).

### Pruned tool surface

`src/anon/` is the tool as evaluated, not the whole tool. The paper's harness exercises eight
CLI verbs — `run`, `extract`, `curate`, `generate`, `drift`, `diff`, `propose` and
`export --graph` — and imports the fact model, the curation / drift stages, the auto-propose
module, the LLM provider and the RQ9 edit-trace reader. Every module that nothing on that path
imports, transitively, is left out of this package together with its tests (the import closure
over `src/` was computed at build time; the pruned CLI registers a subcommand only when its
module is present, so the verbs below are simply absent rather than broken):

| pruned verb | what it did in the full tool |
|---|---|
| `serve` | read-only `/api/v1` HTTP layer plus the GUI (the RQ9 curators' session tooling) |
| `mcp` | the same query primitives as an MCP stdio server |
| `combine` | union of per-repository fact models |
| `fleet` | report over a `combine` output |
| `timeline` | narrate committed fact snapshots |
| `measure` | on-demand timestamped build-artifact measurements |
| `verify` | architecture-as-tests conformance gate |

Kept although not scored, because the replication steps or the shipped artifacts depend on
them: `fetch` / `doctor` (§4 uses them), `diff` (the RQ6 harness), the text `export` formats,
the deployment and contracts extractors (their fragments are part of the shipped
`extracted-facts.json`), and the advisory modules the generator and the enrich stage import
(layout, risk, datasheets, ADR conformance, scenarios — written by every run, read by nothing
in the analysis). The shipped `out/<sys>/architecture/generated/` runs were produced by the
full tool; the pruned modules do not write to the facts, the DSL fragments or the graph export,
so the byte-identity check in the verification section holds against them unchanged.
