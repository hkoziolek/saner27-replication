### 6.4 Fairness controls (pre-registered)

1. One canonical input graph per system, exported once, consumed by all ([§14](#14-experiment-harness--raw-data-schema)).
2. Same entity granularity per comparison run (file primary; target secondary, [§4.1](#41-established-architecture-recovery-metrics-rq1rq3)).
3. Same reference, same metric implementation (ARCADE) for all techniques.
4. Baselines run with author-recommended/default parameters; if tuned, tuning is reported and applied to *all* comparably.
5. LLM baseline pinned to the same `model_id` as enrichment (P§8.3 cache key) and rerun ≥5× to report variance. **The eval pins that deployment to `gpt-5.6-sol`** (Azure AI Foundry, reasoning-tier) — deliberately the *stronger* model here, so the LLM-for-structure comparator is a fair steelman rather than a strawman (a weak model losing proves nothing). Enrichment (RQ4) keeps the cheaper `gpt-5.4-mini`; the recovery baseline is the one place the eval pays for the reasoning tier. Cost model in [§6.2](#62-llm-recovery-baseline-positioning-vs-the-202526-line--rq2).



### 8.2 Degradation-correctness check (tests P§11.6 stopping rules)
Force coverage below the 80% floor (disable L2, or starve a target's evidence) and verify the governance **downgrades findings to advisory** instead of crying wolf or hiding erosion. Metric: **FP-suppression rate** = fraction of would-be-false "disappeared"/violation findings correctly reclassified `coverage-gap`/`UNVERIFIED` when degraded. Ablate the stopping rules on/off to show they matter. This turns P§11.6 from prose into a measured guarantee.

## 10a. Blind-curation experiment (RQ9)

> *The expression-regime protocol. Numbered `10a` to preserve the §11–§20 cross-references; by content it is the sixth experiment, and it is the one that produces a **non-circular** curation-vs-reference number.*

> **⚙️ OPERATIONALIZED 2026-07-17** — the shareable researcher instruction set (roles for
> 4 researchers + facilitator across **two systems** — eShop W3a + blind re-curation, Squidex S1 —
> with per-step time estimates, blinding packets, and the attestation form) is
> [`docs/rq9-blind-curation-runbook.md`](../docs/rq9-blind-curation-runbook.md); it is the
> pre-registration of this section's protocol. Tooling landed the same day:
> `baselines/rq9_blind_curation.py` (`worksheet` rater CSVs that cannot leak the pipeline
> decomposition, `ingest` → rater RSF, `ceiling` Cohen-κ + pairwise-MoJoFM → `ceiling.json`,
> `effort` → `effort.json` incl. %-propose-derived, `score` → the §10a.4 four-row `fidelity.json`
> incl. container-edge F1 via pre-registered greedy max-overlap cluster alignment) and the opt-in
> `ANON_EDIT_TRACE` JSONL edit-trace logger in `arch serve` (`src/anon/edit_trace.py`;
> off by default, lives outside `generated/`). Tests: `tests/test_rq9_blind_curation.py`.

**Why this experiment exists.** RQ1/RQ2 answer *detection* — what the build graph recovers autonomously. But in the expression regime (C#, [§1.2](#12-the-thesis-under-evaluation-what-we-are-actually-testing)) the partition is supplied by a human curator, and a curated MoJoFM/a2a scored against a reference the curator could see is circular ([§13](#13-threats-to-validity) curation-authorship confound): it is assisted-vs-unassisted, ≈100 by construction. This experiment produces the *one* curation-vs-reference number that is **not** circular, plus the effort and stability numbers that are the actual expression-regime contribution. **Core for ≥1 system** (§2, [§18](#18-minimum-publishable-evaluation-vs-full-evaluation)).

### 10a.1 Roles (separation is the whole point)
Filled by **distinct people** wherever the team allows; never one person doing two roles without the wash-out caveat in §10a.3.

| Role | Produces | May see | Must **not** see |
|---|---|---|---|
| **Reference author(s) R₁, R₂** (≥2) | the GT decomposition ([§5.3](#53-reference-architecture-construction-protocol)) from code + project docs | code, project docs | the tool output; each other's mapping (until reconciliation) |
| **Blind curator C** (≥1, ideally 2) | the Anon curation (`mapping-rules.yaml`) | code, project docs, `arch propose` draft, build facts, curate-tree GUI | **`reference.rsf`; R's mappings; any fidelity score** |
| **Neutral scorer** | the ARCADE metrics | all artifacts, after freeze | (authorship revealed only post-scoring) |

C ≠ R₁ ≠ R₂. The *curator ≠ reference author* rule already lives in §5.3; this experiment adds **curator-blind-to-reference** and **curator-blind-to-score**.

### 10a.2 What the curator may and may not use (pre-registered)
- **May:** the repository; the project's own public architecture docs (the same GT-doc sources R used — both transcribe the *project's* intent, which is the legitimate inter-rater setup, not leakage); the deterministic `arch propose` draft; the build-graph facts; the GUI.
- **May not:** `reference.rsf`; R's entity→cluster mapping; **any fidelity score** (no score-driven tuning).
- **Stopping rule (pre-registered):** C stops when the model is *review-complete by their own architectural judgment* (no unmapped first-party target; every container a coherent responsibility) — enforced by construction, since C cannot see the score. Log the full edit trace + wall-clock.

### 10a.3 Blinding integrity
- `reference.rsf` stored outside C's workspace; C attests (checklist) they consulted neither it nor R's mapping.
- **If one person must be both R and C** (small team): author the reference *first*, enforce a ≥7-day wash-out, then curate cold — and document it as a **weaker, self-blinded design** and a stated threat ([§13](#13-threats-to-validity)); self-blinding does not fully neutralise recall. Prefer distinct people; recruit one external curator if at all possible.

### 10a.4 Measures — the RQ9 headline is a 4-row-per-system table
| Row | What | Kind |
|---|---|---|
| no-curation floor vs reference | build graph alone | *detection* (context) |
| best autonomous SAR (ACDC/ARC/WCA/LIMBO) vs reference | unassisted tools | *detection* (context) |
| **blind curator C vs reference** | assisted human via Anon | **expression — the number** |
| **human ceiling R₁-vs-R₂** | inter-rater agreement | **ceiling** |

The claim is "**C approaches the human ceiling where autonomous techniques cannot**" — you cannot beat the ceiling; closing the C-to-ceiling gap is the result. Report MoJoFM, a2a, **and container-edge F1** (curation-resistant: human picks nodes, evidence draws edges).
- **Effort:** rule-lines authored; curate-editor op count; wall-clock minutes; % of `propose` suggestions accepted vs hand-authored → an **effort × fidelity** trade-off plotted against autonomous SAR (≈0 effort, low fidelity). *(The §10a.5 manual baseline was dropped 2026-08-30 — not on the plot.)*
- **Stability:** freeze C's `mapping-rules.yaml`, re-run on a later commit → A8 churn ([§7](#7-ablation-study)); byte-identical re-run ([§9](#9-reproducibility--stability-experiment-rq5)). The assisted artifact is *maintainable*; the manual one is not.
- **Optional pure-detection probe (curation-free):** fix the partition to the *reference's own clusters* and test whether Anon's evidence reproduces the reference's documented container edges (edge-P/R/F1, nodes given). The human never touched this — honest edge detection even in the expression regime.

### 10a.5 Manual-modeling comparator (what RQ9 is really against) — **DROPPED 2026-08-30, not executed**
The right foil for the expression regime is **not** autonomous SAR — it is a human producing the same decomposition **by hand** in a modeling tool (hand-written Structurizr DSL / a drawing tool) from code + docs. Measure their effort and the artifact's **staleness** (no determinism, no drift, no evidence links). RQ9's contribution is that Anon reaches comparable fidelity at comparable-or-lower effort **and** yields a governed, re-derivable, drift-checked artifact the manual process does not.

> **Decision 2026-08-30:** this optional arm (runbook §7, eShop, R-B) **did not run**, and neither did the optional second Squidex curator (R-D, curator variance). Consequences, binding for the paper: (1) no measured manual-vs-assisted effort or fidelity contrast may be claimed — the governance advantages (determinism, drift check, evidence links) are argued as properties, not measured against a hand-made model; (2) curator variance is unmeasured — one curator per system, stated in §13; (3) the executed RQ9 design is exactly the core of the runbook: two raters + one blind curator per system, two systems (eShop W3a, Squidex).

### 10a.7 Detection-vs-expression labelling (the iron rule)
Every RQ9 number is pre-labelled **detection** or **expression**, and **no number crosses the line**: floor / SAR / edge-with-fixed-nodes are *detection*; blind-curator fidelity / effort / stability are *expression*. The paper never presents a curator-set partition score as evidence of detection — that is the whole point of the experiment.

Pre-registered before any inferential test is run (commit the analysis scripts and the pre-registration doc *before* unblinding results).

- **Multiple techniques × systems (RQ2):** Friedman omnibus test across techniques on MoJoFM (and a2a); if significant, **post-hoc Nemenyi** (or pairwise Wilcoxon with **Holm–Bonferroni** correction). Visualise with a **critical-difference (CD) diagram**.
  **Corpus-extension sensitivity (decided 2026-08-30).** Squidex joined the fidelity corpus after the omnibus test had first been run on 8 systems — pre-planned (companion plan §5 step 7), with its `pipeline` row = the reference-blind RQ9 curation (`overlays/squidex-blind-R-C`, the only curated Squidex model, non-circular by construction; Table RQ1 marks it). ## 13. Threats to validity

Pre-registered, four-class, each with a mitigation that is *in the design above* (not hand-waved).

- **Construct.** "Architecturally relevant"/"correct decomposition" is judgement-laden → use **published ground truths** where they exist (ITK/bash), report **inter-rater κ** for expert/doc references ([§5.3](#53-reference-architecture-construction-protocol)), and report multiple metrics (MoJoFM *and* a2a *and* c2c) since each has known blind spots.
- **Internal.** Curation is human-in-the-loop → **freeze locked `mapping-rules.yaml`** per system for ablations ([§7.2](#72-design-notes)); the curator ≠ the RQ8 subject and ≠ the reference author ([§5.3](#53-reference-architecture-construction-protocol)); baselines use the *same* input graph ([§6.4](#64-fairness-controls-pre-registered)). LLM nondeterminism controlled by the content-addressed cache (P§8.3) and the `--no-llm` stability baseline.
- **Internal — the curation-authorship confound (CRITICAL, found 2026-06-14, [note](notes/2026-06-14-llm-in-curation-and-no-curation-floor.md)).** The `--no-llm` flag stops the *tool's* LLM (`enrich`) but **not** the curator: the pilot `mapping-rules.yaml` overlays were authored *by an LLM* (Claude) grouping targets by directory/name. So an LLM is in the *structural* loop, upstream of the tool — and the fidelity numbers reflect an LLM architect's grouping, not the deterministic pipeline alone. **Quantified via the no-curation floor** (cluster files by owning build target / projects as singletons, zero grouping): for **C++ file-granularity the floor already scores 90–100 MoJoFM** (opencv 100.0, ITK 96.9, abseil 89.9), so curation adds only +0–5 — structure is genuinely the build graph. For **C# target-granularity the floor is 11–37** (= the `dir` baseline) and **curation supplies +33 to +60** (OrchardCore 11.6→72.1) — there most of the measured advantage is the LLM-authored grouping, because C# encodes its decomposition in *naming*, not in the dependency graph. → **Mitigations (now mandatory): (1) report the no-curation floor as a standard column beside every curated number ([§15](#15-data-processing--tables--figures-pipeline)); (2) the [§7](#7-ablation-study) A2 ablation is upgraded from optional to required — it isolates the curator's marginal contribution; (3) for headline systems, a *human* curator (or human-vs-LLM curation with κ) must replace the LLM stand-in, so the human-in-the-loop design is validated by an actual human.** Do not claim "the pipeline recovers C# architecture" until (1)–(3) are in.
- **Internal — circularity refinement of the confound (2026-06-14, [note](notes/2026-06-14-a2-curation-ablation.md)).** The follow-up A2 work *largely defuses* the "LLM in the structural loop" finding but introduces a tighter one. The C# grouping the LLM supplied turns out to be a **deterministic source convention** the pipeline can now mine with **no LLM** — three refinement extractors (`extract_csproj_sdk`→`sdk-role`, `extract_orchardcore_manifest`→`module-category`, `extract_plugin_namespace`→`plugin-type`) + the `members_tag` selector reach 100.0 on all three C# systems (the `det_curation` rung). **But two of the three C# references (nopCommerce, OrchardCore) were themselves transcribed from those same conventions, so `det_curation`=100 is a *reconstruction ceiling, not independent fidelity*** — a deterministic rule agreeing with a reference made of the same rule. → **Refined mitigation, superseding (3) above for C#:** report `none` / `det_curation` / `llm_curation` as columns; treat `det_curation` 100.0 as an explicitly-labelled ceiling; and obtain **one independent human reference with κ** (eShop priority — its `BuildingBlocks` role-grouping is the sole C# residual no convention captures) for a genuinely non-circular C# number ([§5.3](#53-reference-architecture-construction-protocol)). The defensible C# claim is *"the architecture is a source-declared convention the pipeline mines deterministically (the pilot LLM merely re-encoded it),"* not *"the pipeline blindly matches an independent human architecture."*
- **External.** Five-ish C++ / five-ish C# OSS systems ≠ proprietary [anonymized] code; **C# has no public ground truth** (asymmetry stated openly); CMake-favoured (MSBuild-C++ is L0-only). → state the OSS→industrial gap; **partially closed 2026-07-12 by the Tier-P extension** ([§5.5](#55-proprietary-corpus-extension-tier-p-org--decided-2026-07-12)) — 3–6 anonymized [anonymized] systems incl. a C++ case whose intended architecture *fights* the directory tree (the counter-example the OSS C++ corpus lacks); the rest of the gap stays open; report which systems we *couldn't* build ([§5.4](#54-selection-criteria--pinning)).
- **External / conclusion — Tier-P non-replicability (NEW 2026-07-12).** Reviewers cannot re-run the anonymized proprietary rows, and anonymization (coded names, bucketed sizes) limits scrutiny of the GT-diag references themselves. → Mitigations in [§14.3](#143-proprietary-data-handling-tier-p): Tier-P rows **corroborate but never solely carry** any claim (pre-registered); the anonymization script + GT-diag protocol are published; κ and delta counts are reported per system; rows are visually marked non-replicable. Residual risk stated: the reader must trust the process, not the artifact.
- **Conclusion.** Small N, multiple comparisons → non-parametric tests, **multiple-comparison correction**, **effect sizes + CIs**, pre-registered thresholds ([§12](#12-statistical-analysis-plan)).
- **LLM-specific (RQ4).** Naming preference is subjective and model-version-dependent → pin the model id (P§8.3), report which model, treat accepted names as a **reviewed artifact** (P§8.5) so the comparison is reproducible, and keep the **structural-diff=0 invariant** as a hard check.
- **Construct — what view is recovered (ADDED 2026-08-31, reviewer M6).** The recovered view is the **module / development view at build-target altitude**, rendered in C4 container/component notation because that is the target DSL; edges are compile-time dependencies (link, include, symbol, ProjectReference). Runtime communication, IPC, messaging, data stores, plugins, and deployment relations are **out of scope and unevaluated** — the deployment and P/Invoke interop extractors exist but feed no RQ. Stated in the paper's §III/§IV and as a threat.
- **Internal / external — the regime confound (ADDED 2026-08-31, reviewer M2).** Build technology, target granularity, architectural style, size, and curation provenance all **co-vary with language** in this corpus, so the "two regimes" are a **build-graph property** (target-granular vs project-coarse builds, measurable by the §12(g) diagnostic) *observed along the language line*, not a language effect — libxml2 (autotools, C) and Terminal (MSBuild-C++, unit ratio 1.0) are the in-language counterexamples. More systems per build idiom are the extension's job.
